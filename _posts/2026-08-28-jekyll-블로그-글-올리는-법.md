다른 사람의 블로그를 보긴 했지만 이번에 Jekyll를 활용하게 된 것은 처음이다. 글을 올리는 것에 생각보다 귀찮은 과정이 들어간다. 이걸 정리해놓고 두고두고 볼 생각이다.

이 순서는 이미 [공식 문서](https://github.com/cotes2020/jekyll-theme-chirpy/wiki)를 보고 `_config.yml`까지 수정했다는 가정 하에 작성되었다.

## 1. 문서 확인

[글 작성 법](https://chirpy.cotes.page/posts/write-a-new-post/)을 참고하였다.

[Front Matter](https://jekyllrb.com/docs/front-matter/)도 마찬가지로 알아보도록 하자.

## 2. [Jekyll-Compose](https://github.com/jekyll/jekyll-compose) 세팅하기

`Gemfile`에 다음 줄을 추가한다. 이 저장소에는 이미 들어 있으므로 중복으로 추가하지 않는다.

```ruby
gem "jekyll-compose", group: [:jekyll_plugins]
```

저장소 루트에서 의존성을 설치하고 사용할 수 있는 명령을 확인한다.

```bash
bundle install
bundle exec jekyll help
```

도움말에 `post`나 `draft`가 보인다면 설치가 끝났다. 설치 중 오류가 발생하면 메시지를 확인하고 Ruby·Bundler의 설치 경로와 권한을 점검한다.

## 3. 포스트 작성

다음 명령을 실행하면 `_posts/`에 날짜와 제목이 포함된 마크다운 파일이 만들어진다.

```bash
bundle exec jekyll post "포스트 제목"
```

파일 첫머리의 front matter를 확인하고 본문을 작성한다. 이 블로그에서 사용하는 기본 형태는 다음과 같다. 제목, 날짜, 분류와 설명은 새 글에 맞게 바꾼다.

```yaml
---
layout: post
title: "포스트 제목"
date: 2026-08-28 10:42 +0900
categories: [일지, 메모]
tags: [jekyll]
description: "이 글에서 다루는 핵심 내용을 한두 문장으로 작성한다."
---
```

`description`은 제목 아래에 표시되는 설명이다. 다이어그램이 있는 글에는 `mermaid: true`, 수식이 있는 글에는 `math: true`를 추가한다.

> 초안 작성엔 `bundle exec jekyll draft "포스트 제목"`을 실행하여 `publish`하는 방법이 있지만 내 성격상 사용하지 않을 것 같다.

## 4. 업로드

먼저 로컬에서 미리보기를 열어 이미지와 코드블록이 의도대로 표시되는지 확인한다.

```bash
bash tools/run.sh
```

미리보기 서버를 종료한 뒤 빌드와 내부 링크를 검사한다.

```bash
bash tools/test.sh
```

변경한 파일을 커밋한 뒤 푸시한다. GitHub Actions의 `Build and Deploy` 워크플로가 성공하면 GitHub Pages에 반영된다.

```bash
git push
```
