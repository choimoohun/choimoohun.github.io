## 시도한 접근 방식

이번 주차에는 입력값이 고정되어있지 않는다. PDF에 있는 테스트케이스를 직접 테스트해보고 내가 테스트케이스를 만들어보기도 해야했다. 지난 주차들보다 상대적으로 자유롭다고 느껴졌다.

게다가 소스 파일 내에 필요한 함수들이 이미 만들어져 있어서 파이썬으로 공부했을 때처럼 간편하게 필요한 함수를 구현할 수 있을 것 같았다.

나는 일주일 내에 모든 문제를 푸는 것을 목표로 잡았었고, 문제를 풀며 동시에 C언어 문법도 익혀 시간을 단축싶었기에 [Gemini Notebook](https://notebook.google.com/)에 PDF를 넣어 번역하고 다음과 같이 문제를 풀어나갔다.

1. 지난 주차처럼 고민하고 고민하며 문제를 해결
2. PDF를 보며 제시된 입력값을 테스트
3. 모든 테스트가 정상적으로 출력이 되는 것을 확인하면 이제 AI에게 코드 리뷰를 맡긴다.
4. 코드를 개선하며 학습
5. 다음 문제도 반복...

AI에게 코드 리뷰를 맡기다보니 생각보다 비효율적인 코드를 많이 작성하고 있었다는 걸 알 수 있었다. 인자가 잘못 전달될 경우의 예외 처리라던지 다른 테스트 케이스에서는 기대값과 출력이 다르다던지 등을 알려주었고, 코드 줄 수를 줄인다던지 등의 여러 개선점들을 찾아보았다.

한 번 정도 `main()`을 보다가 여러 생각이 들었다.

- '`int`를 `bool` 대신 쓰는구나.'
- '스택 문제인데 왜 스택을 `main()`에 만들어놓고 인자로 전달하지 않지? 그냥 내가 매개변수 추가해서 넣어야지.'

이런 식으로 문제를 풀었는데 문제들이 내 기준으론 모두 재밌었다. 시간만 많았으면 찬찬히 살펴볼텐데 아쉽다는 생각이 들었다.

## 문제와 해결 과정

의도되지 않은 동작을 많이 봤다. 노드가 정상적으로 교체되지 않은 적도 있었고, 무한 루프를 볼 때도 있었다. 특히 `Segmentation fault`를 많이 보았다. 이런 문제들은 대체로 포인터에 익숙하지 않아 발생한 문제들이었다.

이때 포인터에 대한 공부를 다시 하게 되었고 이 과정에서 AI의 도움을 받기도 했다. Gemini 채팅이 총 15개가 쌓였는데 5개가 포인터 관련 내용으로 학습한 내용이었다. 내가 포인터를 이해하는 방식은 이랬다.

```c
int *ptr; // (int) *ptr: int의 주소
ListNode *head; // (ListNode) *head: ListNode의 주소
ListNode **ptrHead; // (ListNode*) *ptrHead: ListNode의 주소의 주소
```

```c
ListNode *pre = *ptrHead;
ListNode *cur = (*ptrHead)->next;

ListNode *max = *ptrHead;
ListNode *preMax = NULL;
```

원래는 `(*ptrHead)->next`가 가능하다는 것 조차 몰랐는데 필요하다면 변수를 여러 개 선언하는 것으로 쉽게 문제를 해결할 수 있었다. 이번 주차를 통해 코드 줄 수를 줄이는 게 능사가 아니라 일단 해야할 동작을 명확하게 아는 것이 중요하다는 것을 깨달았다.

## 새롭게 배운 점

- 앞으로 버그가 생길 때마다 무엇으로 인해 버그가 생겼는지 기록하는 습관을 들여야겠다.
- 삽입/삭제에 따라 크기가 변하는 연결 리스트를 순회할 때는 처음의 크기를 기준으로 순회한다.
- RAM은 디스크와 페이징 방식을 통해 사용되지 않는 데이터를 디스크의 스와핑 영역에 넣고, 필요한 데이터를 뺀다.
- `ary`는 읽기 전용 상수이며 증감연사자를 붙이면 에러가 발생한다.
- `ary[2] = *(ary + 2)`
- 메모리에 저장되는 것은 단순한 비트의 나열이고 이를 타입으로 받아들이는 것은 레지스터를 통해 이루어진다.
